golden-agent (Python)

A small Python library for building agents from the core elements: model, instructions, tools, loop and state, plus a guard layer and sub agents. Standard library only, no framework, no dependencies. Define a few pieces, build an Agent, call run. It is the Python version of the Java library and behaves the same way.

Python 3.10 or newer Zero dependencies 34 tests pass Packaged as a wheel

OverviewWhat it is and why

Agent frameworks bundle the same handful of ideas. This library keeps those ideas visible and small, so you can read all of it, change any part, and use it as the base for new agents without adopting a large framework.

5core elements, each a small class or protocol
3gate outcomes: allow, deny, ask a human
0runtime dependencies
34unittest tests: 25 ported from the Java checks, 9 for the Anthropic adapter
The design rule behind it: the LLM proposes and never executes. Your code validates, gates and runs every action.

StructureArchitecture and modules

One public entry point (Agent) sits on top of the loop, and the loop depends only on small abstractions. Dependencies point downwards, so every piece can be replaced.

Get goingQuick start

from golden_agent import Agent, Gates, Instructions

agent = (
    Agent.builder("support")
    .model(model_client)                                                 # 1. model
    .instructions(Instructions.for_role("You are a support agent.")      # 2. instructions
                  .with_rule("Verify the customer before changing an account."))
    .tools(GetCustomerTool(), RefundTool())                              # 3. tools
    .gate(Gates.prerequisites({"process_refund": {"get_customer"}}))
    .gate(Gates.require_approval({"process_refund"}, "refunds need approval"))
    .approver(lambda call, reason: ask_a_person(call, reason))
    .max_iterations(10)                                                  # 4. loop limits
    .build()
)

result = agent.run("Refund order O-1 for customer C-1")                  # 5. fresh state per run
print(result.status.name, result.text)

Keyword construction works too:

agent = Agent("support", model=model_client, instructions=Instructions.for_role("..."),
              tools=[GetCustomerTool()], sub_agents=[researcher], gate=[rule_one, rule_two])

Guarantees, each covered by a test

  • The loop branches only on stop_reason. It never parses text such as "I'm done".
  • The full message history is sent on every call. Each run creates a new, isolated state.
  • Unknown tools, bad arguments and tool failures become error results the model can read. Internal details are not leaked.
  • A denied call never runs, and an ask-a-human decision with no approver is denied.
  • iterations equals the number of tool rounds plus one.

Guard layerGates, humans and filters

A gate is a plain function (tool_use, state) -> Decision that runs before every tool call, outside the model. It returns one of three decisions:

Allow()
the tool runs
Deny(reason)
the model receives an error result with the reason
AskHuman(reason)
the approver decides. No approver means deny
PiecePurpose
Gates.prerequisites(mapping)Block a tool until other tools have succeeded, for example refund only after the customer is verified
Gates.require_approval(tools, reason)Ask a human before the named tools run
Gates.allow_list(tools)Only the named tools may run
all_of(gate_a, gate_b)Combine gates. The first non-Allow decision wins. The builder's .gate() does this for you
ApproverA function (tool_use, reason) -> bool. Plug in a console prompt, ticket, chat message or web form. Default is deny-all
Result filterA function (tool_use, output) -> ToolOutput that runs after the tool and before the model sees the result. Trim, normalise or redact

Multi-agentCoordinator and sub agents

An agent can be given to another agent as a tool. The coordinator is just an Agent whose tools are delegation tools.

researcher = (
    Agent.builder("researcher")
    .description("Finds facts on a topic and returns claims with sources")
    .model(researcher_model)
    .instructions(Instructions.for_role("You are a research agent."))
    .tool(web_search_tool)
    .build()
)

coordinator = (
    Agent.builder("coordinator")
    .model(coordinator_model)
    .instructions(Instructions.for_role("You are a coordinator."))
    .sub_agent(researcher)            # becomes the tool delegate_to_researcher
    .sub_agent(analyst)
    .build()
)
  • Isolation: a sub agent sees only the task and context the coordinator passes. It never sees the coordinator's conversation.
  • Least privilege: each agent has only its own tools. Use ToolRegistry.subset(...) to share part of a toolset.
  • Structured failure: if a sub agent does not finish, the coordinator receives an error result such as SUB_AGENT_FAILURE agent=... status=NOT_FINISHED iterations=... note=... task=... partial=..., never an empty success. It can then retry, route elsewhere or continue with partial results.
  • Reuse: an Agent holds no run state, so one instance can be run many times, even concurrently.

Make it yoursExtension points

Models and tools are anything with the right methods (structural typing), and gates, approvers and filters are plain callables. To extend the library you add code and do not change it.

A typed tool

@dataclass(frozen=True)
class RefundRequest:
    order_id: str
    amount_cents: int


class RefundTool(TypedTool[RefundRequest, str]):
    def __init__(self) -> None:
        super().__init__(ToolDefinition(
            "process_refund",
            "Refund an order. Requires a verified customer. Returns a confirmation.",
            InputSchema.object()
            .string("orderId", "The order id")
            .integer("amountCents", "Refund amount in cents")
            .build()))

    def decode(self, input):
        return RefundRequest(self.string(input, "orderId"), self.integer(input, "amountCents"))

    def run(self, request):
        return f"refunded {request.amount_cents} cents"

A custom gate

def business_hours(call: ToolUse, state: AgentState) -> Decision:
    if call.name == "process_refund" and not is_business_hours():
        return deny("Refunds are only processed during business hours")
    return allow()

agent = Agent.builder("support")...gate(business_hours).build()

Reuse itUse it as a library

Build once, then install the wheel anywhere. The wheel was installed into a clean virtual environment with no network, and a separate program that imported the installed package built and ran a working agent.

# run the tests and the demo, and build the wheel
.\build.ps1                    # Windows
./build.sh                     # macOS and Linux

# result
dist/golden_agent-1.0.0-py3-none-any.whl

# use it from your own project
pip install dist/golden_agent-1.0.0-py3-none-any.whl
pip install .                  # straight from the folder
pip install -e .               # editable, while working on the library

Honest notesLimits and what is not included

Not run against the live API. AnthropicModelClient has offline tests for its request and response mapping and its retry behaviour, using a fake transport, but it has not been run against the real service from this repository. Test it with your own key first. You choose the model id.
  • Python version: requires 3.10 or newer because it uses structural pattern matching. Verified on Python 3.12.6 only, since that was the version available.
  • Not included on purpose: streaming, long-term memory, context compaction, parallel tool execution, parallel sub agents, persistence and tracing. Each one fits behind an existing extension point.
  • Sequential execution: tools in one response run one after another.
  • Tool input is a mapping: tool arguments arrive as a dictionary. TypedTool decodes them into your own type, and there is no automatic schema validation beyond required arguments.
  • Wheel build: needs setuptools. It was available offline here, and the build script reports clearly if it is not.
