golden-agent

A small Java library for building agents from the core elements: model, instructions, tools, loop and state, plus a guard layer and sub agents. Plain Java, no framework, no dependencies. Define a few pieces, build an Agent, call run.

OverviewWhat it is and why

Agent frameworks bundle the same handful of ideas. This library keeps those ideas visible and small, so you can read all of it, change any part, and use it as the base for new agents without adopting a large framework.

5core elements, each a small interface or type
3gate outcomes: allow, deny, ask a human
0runtime dependencies
25plain-Java self-checks, no test framework
The design rule behind it: the LLM proposes and never executes. Your code validates, gates and runs every action.

StructureArchitecture and packages

One public entry point (Agent) sits on top of the loop, and the loop depends only on small abstractions. Dependencies point downwards, so every piece can be replaced.

Get goingQuick start

Agent agent = Agent.builder("support")
        .model(modelClient)                                              // 1. model
        .instructions(Instructions.forRole("You are a support agent.")   // 2. instructions
                .withRule("Verify the customer before changing an account."))
        .tools(new GetCustomerTool(), new RefundTool())                  // 3. tools
        .gate(Gates.prerequisites(Map.of("process_refund", Set.of("get_customer"))))
        .gate(Gates.requireApproval(Set.of("process_refund"), "refunds need approval"))
        .approver((call, reason) -> askAPerson(call, reason))
        .maxIterations(10)                                               // 4. loop limits
        .build();

AgentResult result = agent.run("Refund order O-1 for customer C-1");     // 5. fresh state per run
System.out.println(result.status() + ": " + result.text());

model asks for get_customer     -> tool_result: customer C-1 is verified

                                   tool_result: refunded 9000 cents for order O-1
ASSISTANT says: The refund of 9000 cents for order O-1 has been processed.

The model tried to skip the verification step. The gate refused, the model recovered, and a human approved the last step.

Guarantees, each covered by a self-check

  • The loop branches only on stop_reason. It never parses text such as "I'm done".
  • The full message history is sent on every call. Each run creates a new, isolated state.
  • Unknown tools, bad arguments and tool failures become error results the model can read. Internal details are not leaked.
  • A denied call never runs, and an ask-a-human decision with no approver is denied.
  • iterations equals the number of tool rounds plus one.

Guard layerGates, humans and filters

A Gate is ordinary programmatic code that runs before every tool call, outside the model. It returns one of three decisions:

Allow
the tool runs
Deny(reason)
the model receives an error result with the reason
AskHuman(reason)
the HumanApprover decides. No approver means deny
PiecePurpose
Gates.prerequisites(map)Block a tool until other tools have succeeded, for example refund only after the customer is verified
Gates.requireApproval(tools, reason)Ask a human before the named tools run
Gates.allowList(tools)Only the named tools may run
gate.and(other)Combine gates. The first non-Allow decision wins
HumanApproverPlug in a console prompt, ticket, chat message or web form. Default is deny-all
ResultFilterRuns after the tool and before the model sees the result. Trim, normalise or redact

Multi-agentCoordinator and sub agents

An agent can be given to another agent as a tool. The coordinator is just an Agent whose tools are delegation tools.

Agent researcher = Agent.builder("researcher")
        .description("Finds facts on a topic and returns claims with sources")
        .model(researcherModel)
        .instructions(Instructions.forRole("You are a research agent."))
        .tool(webSearchTool)
        .build();

Agent coordinator = Agent.builder("coordinator")
        .model(coordinatorModel)
        .instructions(Instructions.forRole("You are a coordinator."))
        .subAgent(researcher)            // becomes the tool delegate_to_researcher
        .subAgent(analyst)
        .build();
  • Isolation: a sub agent sees only the task and context the coordinator passes. It never sees the coordinator's conversation.
  • Least privilege: each agent has only its own tools. Use ToolRegistry.subset(...) to share part of a toolset.
  • Structured failure: if a sub agent does not finish, the coordinator receives an error result such as SUB_AGENT_FAILURE agent=... status=NOT_FINISHED iterations=... note=... task=... partial=..., never an empty success. It can then retry, route elsewhere or continue with partial results.
  • Reuse: an Agent holds no run state, so one instance can be run many times, even concurrently.

A typed tool

record RefundRequest(String orderId, int amountCents) { }

final class RefundTool extends TypedTool<RefundRequest, String> {
    RefundTool() {
        super(new ToolDefinition("process_refund",
                "Refund an order. Requires a verified customer. Returns a confirmation.",
                InputSchema.object()
                        .string("orderId", "The order id", true)
                        .integer("amountCents", "Refund amount in cents", true)
                        .build()));
    }
    protected RefundRequest decode(Map<String, Object> in) throws ToolException {
        return new RefundRequest(string(in, "orderId"), integer(in, "amountCents"));
    }
    protected String run(RefundRequest r) { return "refunded " + r.amountCents() + " cents"; }
}

Gate businessHours = (call, state) ->

Reuse itUse it as a library

Build once, then depend on the jar from any project. A separate test program that used only the packaged jar built and ran a working agent.

# build, run the 25 self-checks and the demo, and package the jar
.\build.ps1                    # Windows
./build.sh                     # macOS and Linux

# result
dist/golden-agent-1.0.0.jar
dist/golden-agent-1.0.0-sources.jar

# use it from your own project
javac -cp golden-agent-1.0.0.jar MyApp.java
java  -cp golden-agent-1.0.0.jar;. MyApp       # use : instead of ; on macOS and Linux

Honest notesLimits and what is not included

Not run against the live API. AnthropicModelClient has offline checks for its request and response mapping, but it has not been run against the real service from this repository. Test it with your own key first. You choose the model id.
  • Java version: compiled with --release 21 and no preview features. Verified on JDK 23 only, since that was the version available.
  • Not included on purpose: streaming, long-term memory, context compaction, parallel tool execution, parallel sub agents, persistence and tracing. Each one fits behind an existing extension point.
  • Sequential execution: tools in one response run one after another.
  • Tool input is a map: there is no JSON library, so tool arguments arrive as Map<String,Object>. TypedTool decodes them into your own type.
